This release makes a command that does not reach your device say so, and
fixes a setpoint that jumped back after you changed it.

### 🔧 A setpoint that stays where you put it

On a room following its programme, typing a new temperature switched it to
override and then showed the old setpoint again for about ten seconds
before settling. The new value now shows once and stays. Checked on a
Navizone room ; every device with a programme override takes the same path.

### ⚠️ A refused command is now an error

When Cozytouch cannot carry out a command, Home Assistant now shows why :
the cloud cannot be reached, the device is offline, or the command was not
carried out. It used to do nothing and leave the entity as it was. An
automation or script that sends a refused command now stops at that step,
unless the action has `continue_on_error`. When an absence is refused, the
away switch goes back to what the device reports instead of staying on.

### 🔍 Refusals in the diagnostics dump

The diagnostics file now lists the last twenty refused commands, with the
device, the value sent and the reason, so a device report carries what
only the log used to. Each refusal is still logged as a warning.
